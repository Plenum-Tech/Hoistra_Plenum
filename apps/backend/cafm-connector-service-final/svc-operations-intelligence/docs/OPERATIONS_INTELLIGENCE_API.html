Mass import §3.1

Ingest up to 5 compliance PDFs in one call — classified, field-extracted, forgery-checked and saved as drafts in parallel, one document_id each. One file failing never blocks the others.

POST /ingest-batch New

Parallel bulk ingest. Each file → classify → extract → draft upsert (which itself fires membership-pending, the PM-confirm approval, and auto-verify). Max 5.

Request
{
  "files": [                // 1–5
    {
      "document_id": "uuid",   // from doc-rag
      "file_name": "epc.pdf",
      "source_text": "...",    // or
      "pdf_base64": "...",
      "certificate_type_code": null, // optional; else classified
      "cert_scope": null,
      "site_id": null, "vendor_id": null
    }
  ],
  "organization_id": "uuid",
  "country_code": "UK"
}
Response
{
  "ok": true, "batch_id": "uuid",
  "requested": 3, "succeeded": 3, "failed": 0,
  "results": [{
    "ok": true, "stage": "done",
    "document_id": "uuid",
    "certificate_id": "uuid",
    "certificate_type_code": "EPC",
    "cert_scope": "Building",
    "status": "Current",
    "classification": {"method":"claude","confidence":"high"},
    "requires_pm_confirmation": true,
    "membership_queue_item_id": "uuid",
    "verification": { /* §8 result */ },
    "error": null
  }]
}
TS client 
ingestComplianceBatch({ files, organizationId?, countryCode? })
Draft, not final. Every file lands as a draft awaiting PM confirm + a Keep/Remove membership card. Reject a 6th file with 422.

Accreditation verification §8

Verify a certificate against its authoritative source. These endpoints existed but were non-functional until the sources table + register store were fixed — 15 cert types now return real verified results (EPC/DEC/TM44 keyless, ESOS via Companies House, EL/PL insurance via FCA, 8 data-dump registers).

POST/verifyFixed

Verify by type + identifiers. Picks the channel (public_api / data_dump / website) and returns the register result.

  "certificate_type_code": "EPC",
  "certificate_number": "0568-…-8254",
  "vendor_name": null, "company_number": null,

  "certificate_id": null, "persist": true

{
  "ok":true, "verified":true,

Alerts & approvals queue §9 · the alert table

The single queue behind every compliance alert. Each row is one item; item_type tells you which alert it is, and any row with an email_draft is a ready-to-send message (renewal / forgery / verification). This is the table the alert UI reads and the "Confirm & send" button writes to.

GET/approvals

List queue items (alerts). Query: status=pending, source_feature=A, organization_id, limit.

{ "ok":true, "count":…, "items":[{
  "id":"uuid", "item_type":"vendor_email",
  "severity":"Critical", "status":"pending",
  "summary":"Lapsed: Acme — SIA ACS",
  "related_entity_type":"vendor", "related_entity_id":"uuid",
  "payload":{ "certificate_id","risk",… },
  "email_draft":{ "to","subject","body","mailto_uri" }
}] }

POST/certificates/renewal-email

Draft & queue a renewal email for one certificate. { certificate_id? | certificate_number? } → { ok, queue_item_id, email_draft }. TS: draftRenewalEmail().

GET/approvals/one-click/{token}

Email one-click links (from alert emails). /peek loads the item for the in-app deep-link; POST /redeem applies the Approve/Acknowledge. TS: peekEmailApprovalToken() · redeemEmailApprovalToken().

PATCH/certificates/{id}/remedial-status

Set remedial status on a Fail/C1 item. { remedial_status: "Open"|"In Progress"|"Closed" }. Also: POST /building-change invalidates certs after a building change (raises alerts). TS: setRemedialStatus() · flagBuildingChange().
