# Country-pack taxonomy and applicability

Target policy: specification v0.37.0.

Follow the shared policies and reviewed Compliance instructions when
explicitly loaded. Use only an enabled authorized taxonomy/coverage adapter.
Its presence in legacy code does not make it available in homework.

## 1. What the question asks

Distinguish a question about pack types/requirements from a question about
what records a building or vendor holds. Do not infer the pack from the
existing register, and do not add a portfolio status report to a pure
taxonomy question unless requested.

If the requested jurisdiction, pack version, subject or applicability is
unclear and materially changes the result, clarify rather than guess.
Do not assume every caller or building is in the UK.

## 2. Returned authority and applicability

Identify the returned country pack/version and source basis. Describe it
as the application's recorded pack, with applicability and limitations.
Do not present unverified or stale pack content as a fresh legal verification.
Use only returned requirement names, codes, references and intervals.
If required evidence is unavailable, say so instead of inventing a rule.

Separate Building-scope and Vendor-scope types when the question asks for
both; do not force both into a one-scope question.

A pack can contain types that do not apply to every building/vendor.
Describe supported applicability conditions separately. Do not turn
unknown applicability into either a required obligation or an exemption.
Homework fixture quantities and HOI checklists are not legal obligations.

## 3. Counts and complete lists

Use backend counts for the returned pack version, requested subject and
filters. Do not hardcode 55/27/28 or another historical pack total.
Count types, not certificate rows, and keep scopes/trades distinct.

A list claiming completeness must account for the requested types once,
using returned codes/names. Do not omit a type merely because no document
is held, duplicate entries to reach a total or move types between scopes.
For incomplete retrieval, label the list partial and use a verified total
only where it covers the same population. Do not fabricate certificate IDs
for taxonomy entries that have no certificate record.

## 4. Held, missing and coverage

Only include held/missing status when the question asks for that comparison
and an authorized coverage adapter establishes it.

Pack types on file / pack types is pack completeness, not overall compliance,
safety or HOI. Building-specific applicable coverage requires verified
applicability, not a universal pack denominator.

State the denominator and source/version. Held+missing equals the total
only where the backend establishes disjoint exhaustive categories.
An expired or suspect certificate can be on file without establishing a
currently satisfied obligation; preserve that distinction.

## 5. Presentation and limits

Lead with the requested taxonomy answer. Group by scope/trade where useful,
using returned references and intervals. No tiles, UI groups, Saved Space
or fixed narrative shape are required for Homework 1.

Do not invent tool/filter names, perform unrestricted schema queries or
expand building/vendor disclosure because taxonomy was requested.
No renewal, block/unblock, booking, source edit or email action follows
automatically from a taxonomy answer.
