Purpose: Retrieved by RAG system to resolve ambiguous table and column names

HOW THIS DOCUMENT IS USED
When a source table or column name fails deterministic matching (exact match below
95% confidence), this document is retrieved to find synonym clusters, contextual
descriptions, and linguistic variants that help identify the correct canonical
FM entity. Each section is designed to be semantically dense with real FM
language, abbreviations, trade terminology, and cross-standard synonyms.

ENTITY CLUSTER: SITE
Canonical Name: Site
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
A Site is the top-level physical location unit in facilities management. In
property management it is called a property, estate, campus, or portfolio
asset. A site contains one or more buildings and is the primary unit at
which budgets, compliance obligations, and management contracts are held.
In the UK, a site typically maps to a single freehold or leasehold property.
In the US it maps to a property or campus. In the Middle East it is often
called an asset or development.

SYNONYMS AND ALTERNATIVE NAMES (how this appears in source data):
property, estate, campus, development, asset, location, facility, site-id,
property-id, estate-id, campus-id, site_code, site_ref, site_name,
site_description, property_name, property_code, estate_name, estate_code,
location_name, location_id, loc-id, loc_id, facility_name, facility_code,
premises, premises_name, premises_id, address, address_line_1, building_site,
managed_property, client_property, portfolio_asset, managed_estate,
managed_facility, project_site, construction_site, post-handover_site

COBie v3 EQUIVALENT:
Sheet: COBie.Facility
Key column: Name (facility name is the site name)
Category column: Facility.Type (values: Facility, Project, Site)
The COBie Facility sheet covers both Site and Building. Site is implied
when the Facility.Type is Site or when multiple buildings are listed
under one Facility Name. ExternalSystem and ExternalObject columns link
back to the originating system.

BRICK SCHEMA EQUIVALENT:
Class: brick:Site
URI: https://brickschema.org/schema/Brick#Site
A brick:Site is the top-level location entity. It contains brick:Building
instances via the brick:hasPart relationship. In RDF the site is identified
by a URI such as ex:site_22bishopsgate or similar.

FIELD NAME PATTERNS IN SOURCE DATA:
Fields whose names contain the words: site, property, estate, campus,
facility (when at the top level), location (when top-level and not a room),
premises, development. Also: SITEID (Maximo), WERKS (SAP Plant), site-id
(Archibus), triProperty (TRIRIGA), Code or Name on top-level location records.

ENTITY CLUSTER: BUILDING
Canonical Name: Building
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
A Building is an individual structure within a Site. In commercial property
management, a building is a single tower, block, or structure that has its
own address, GIA (Gross Internal Area), floor count, and potentially its own
EPC (Energy Performance Certificate). Multi-building sites have separate
buildings for each structure. A building contains floors, zones, and rooms.
In the UK, a building may be referred to as a block, tower, or unit. In
residential FM, a building is often called a block or court. In retail,
a building is a unit or store. In industrial/logistics, a building is a
unit, warehouse, shed, or distribution centre.

SYNONYMS AND ALTERNATIVE NAMES:
building, block, tower, unit, structure, warehouse, shed, distribution_centre,
distribution_center, dc, store, court, mansion_block, residential_block,
office_building, industrial_unit, block_name, block_id, block_code,
tower_name, tower_id, bl-id, bl_id, bldg, bldg_id, bldg_code, bldg_name,
building_id, building_code, building_name, building_ref, building_number,
building_desc, building_description, structure_name, structure_id

COBie v3 EQUIVALENT:
Sheet: COBie.Facility
Key column: Name (each row = one building when used at building level)
The COBie Facility sheet uses a single sheet for both Site and Building.
A building-level COBie Facility has specific attributes like GrossArea,
NetArea, NumberOfFloors. The Level sheet (COBie.Level) lists floors under
a Facility name, providing the link between building and floor.

BRICK SCHEMA EQUIVALENT:
Class: brick:Building
URI: https://brickschema.org/schema/Brick#Building
Relationship: brick:Site brick:hasPart brick:Building
A brick:Building contains brick:Floor instances. The Building entity
captures the overall structure within which systems and equipment operate.

FIELD NAME PATTERNS:
bl-id, bl_id, bldg, building, structure, block, tower. Archibus uses
the BL table with bl-id as the primary key. Maximo uses LOCATIONS with
TYPE=BUILDING. SAP uses Functional Location level 2.

ENTITY CLUSTER: SPACE
Canonical Name: Space
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
A Space is any discrete physical area within a building that can be
identified, measured, and managed. Spaces include floors, zones, rooms,
corridors, plant rooms, risers, voids, roof areas, car park levels, and
common areas. In property management, a space is the unit of lettable area
associated with a tenant. In FM operations, spaces are the locations where
assets are installed and where work orders are raised. A space can contain
other spaces (a floor contains rooms; a zone contains sub-zones). A room
is the smallest defined space unit.

ENTITY CLUSTER: ASSET
Canonical Name: Asset
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
An Asset is any physical piece of equipment, plant, component, or building
fabric element that requires maintenance, inspection, or management. Assets
are the primary unit of FM work. Every planned preventive maintenance (PPM)
schedule, reactive work order, and compliance certificate is associated with
one or more assets. Assets range from large plant items (chillers, boilers,
generators) to small components (individual fire detectors, access control
readers, tap heads). In the UK FM industry, assets are also called plant
items, equipment, kit, fixed assets, installed assets, M&E assets,
hard FM assets, or building components. Assets that are part of a larger
system are called sub-components or child assets.

ENTITY CLUSTER: ASSETTYPE
Canonical Name: AssetType
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
The AssetType is the classification or category of an asset — what type of
equipment it is, independent of the specific instance. Every asset is of a
type. The type defines the maintenance requirements, inspection frequency,
statutory obligations, and contractor accreditation needed. In FM practice
this is called asset category, asset class, equipment type, equipment
standard, equipment classification, or plant category.

SYNONYMS AND ALTERNATIVE NAMES:
asset_type, asset_category, asset_class, equipment_type, equipment_category,
equipment_class, equipment_standard, plant_type, plant_category, plant_class,
component_type, component_category, device_type, item_type, kit_type,
classification, type_code, type_name, type_description, category_code,
category_name, class_code, class_name, eqstd, asset_type_id, type_id,
type_ref, category_ref, assettype, classstructure, eqtyp, klah, dokar,
uniclass_code, omniclass_code, classification_code, classification_system

COBie v3 EQUIVALENT:
COBie.Type — the template record from which Component instances are drawn
  AssetType field values: Fixed (bolted/installed), Moveable (portable)
  Category field references: OmniClass Table 23 (Products) for North America,
  Uniclass Pr table for UK, or custom classification codes

BRICK SCHEMA EQUIVALENT:
BRICK uses its own class hierarchy as the asset type system. The class of
a brick:Equipment instance IS its type. There is no separate AssetType
entity in BRICK. The Uniclass 2015 Ss (Systems) codes provide a parallel
UK classification system. Common type identifiers: AHU, FCU, CHR (chiller),
BWR (boiler), LFT (lift/elevator), GEN (generator), FAS (fire alarm system),
ACS (access control), CCTV, BMS, SWB (switchboard), DB (distribution board),
MDB (main distribution board), UPS, VSD/VFD, HEX (heat exchanger),
CWT (cooling tower), PHE (plate heat exchanger), DHW (domestic hot water),
CWST (cold water storage tank)

ENTITY CLUSTER: WORKORDER
Canonical Name: WorkOrder
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
A WorkOrder is the fundamental operational record in FM — a documented
instruction to carry out maintenance, repair, inspection, or other work
on an asset or space. In UK FM, a work order is also called a job, task,
job card, work ticket, maintenance request, fault report, defect report,
reactive call, callout, or reactive job. Planned maintenance work orders
are called PPM jobs, PM tasks, or planned tasks. An emergency work order
is called an emergency callout, P1 job, or critical reactive. The work
order tracks who reported the fault, what was found, who attended, when
they attended, what they did, how long it took, and what it cost.

ENTITY CLUSTER: CONTRACT
Canonical Name: Contract
-----------------------------------------------------------------------------

WHAT IT IS IN FM TERMS:
A Contract is the formal legal agreement between the building owner or
managing agent and a vendor, defining scope, duration, cost, and SLA terms.
In UK FM, contracts are also called: service contracts, maintenance contracts,
service agreements, framework agreements, call-off contracts, PPM contracts,
TFM contracts, outsourcing contracts, supplier agreements, SLA agreements.
The SLA (Service Level Agreement) section of the contract defines response
and completion time targets for different work order priorities.

Canonical Name: ComplianceCertificate
-----------------------------------------------------------------------------

  System.Category → system type (references OmniClass Table 21 or Uniclass EF)
  System.PartOf → parent system reference
  System.Component.Name → child Asset records within this system
  Example: AHU System (System) contains AHU Fan, AHU Coil, AHU Filter (Components)

COBie.Resource → FM UDR: Resource
  Resource.Name → Resource.trade or ResourceSkill.skill_type
  Resource.Category → Resource classification
    Labor = human resource (Resource entity)
    Material = spare part (SparePart entity)
    Tools = equipment used during maintenance
    Training = training resource

COBie.Job → FM UDR: WorkOrder + PPMSchedule
  Job.Name → WorkOrder.title or PPMSchedule.schedule_name
  Job.Description → WorkOrder.fault_description or PPMSchedule.task_description
  Job.TaskNumber → work order step or task sequence number
  Job.Category:
    Inspection → ComplianceCertificate inspection job or WorkOrder (type=Inspection)
    Preventive / Operation → PPMSchedule
    Emergency / Safety / Trouble → WorkOrder (type=Reactive/Emergency)
    Calibration → WorkOrder (type=Inspection for calibration)
    Adjustment → WorkOrder (type=Planned)
    StartUp / ShutDown → PPMSchedule (seasonal)
  Job.Duration → WorkOrder.labour_hours or PPMSchedule.estimated_duration_hours
  Job.DurationUnit → unit for duration (Day, Minute, Month, Quarter, Week, Year)
  Job.Interval → PPMSchedule.frequency_value (how often this job recurs)
  Job.IntervalUnit → PPMSchedule.frequency_unit
  Job.Priors → prerequisite job names (task sequencing)
  Job.Resource.Name → WorkOrder.resource_id or vendor trade requirement
  Job.Table + Job.Table.Name → links job to entity (Component, Space, Type etc.)
  Job.Status:
    Not Yet Started → PPMSchedule (not yet triggered)
    Started → WorkOrder (status=In Progress)
    Completed → WorkOrder (status=Completed)

COBie.Event → FM UDR: WorkOrder (instance of a Job)
  Event.Name → WorkOrder.workorder_ref
  Event.Company.Name → WorkOrder.vendor_id
  Event.Job.Name → WorkOrder.ppm_schedule_id or job reference
  Event.StartDate → WorkOrder.start_date
  Event.EndDate → WorkOrder.completion_date

COBie.Document → FM UDR: Document
  Document.Name → Document.document_name
  Document.Category:
    Certificates → ComplianceCertificate document
    Operation and Maintenance → O&M manual
    Manufacturer Instructions → installation/service manual
    Shop Drawings → as-built drawing
    Contract Drawings → design drawing
    Contract Specifications → specification document
    Product Data → product data sheet (PDS/TDS)
    Test Reports → test/commissioning report
    Punch List Items → defect list
  Document.Stage → As Built, Approved, Submitted, Exact Requirement
  Document.Table → entity type this document is attached to
  Document.Table.Name → specific entity name (FK)
  Document.ApprovalBy → Document.author or approval authority
  Document.Path + Document.File → Document.storage_path + file_name

COBie.Attribute → FM UDR: (additional attributes on any entity)
  Used for all non-standard fields not captured in core COBie sheets.
  Attribute.Table → entity type (Asset, Space, Component, Type, Zone, etc.)
  Attribute.Table.Name → specific entity name this attribute belongs to
  Attribute.Name → attribute/column name
  Attribute.Value → attribute value
  Attribute.Unit → unit of measure
  Attribute.AllowedValues → valid values list

COBie.Risk → FM UDR: Incident (extension entity)
  Risk.Category → risk type (Change, Claim, Coordination, Environmental,
    Function, IndoorAirQuality, Installation, RFI, Safety, Specification)
  Risk.Consequence → risk consequence
  Risk.LevelOfRisk → Very High, High, Moderate, Low, Unknown
  Risk.Likelihood → Has Occurred, High, Moderate, Low, Unknown
  Risk.Mitigation → mitigation action or control measure
